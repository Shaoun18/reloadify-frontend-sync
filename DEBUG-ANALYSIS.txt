================================================================================
ISSUE #1: CRITICAL ERROR ROOT CAUSE
================================================================================

Problem:
  apply_runtime_overrides() is called at plugins_loaded hook
  But Reloadify_Settings might not be loaded yet
  ini_set() on admin pages causes fatal error on first load

Location:
  reloadify-frontend-sync.php line 123:
  add_action( 'plugins_loaded', [ 'Reloadify_Performance', 'apply_runtime_overrides' ], 0 );

Why It Fails:
  1. plugins_loaded hook fires VERY early
  2. Database might not be fully initialized
  3. get_settings() tries to access options table
  4. ini_set() without error checking causes fatal error
  5. No try-catch or error handling

Fix:
  1. Defer apply_runtime_overrides to admin_init (admin only)
  2. Add error handling for ini_set
  3. Add capability checks
  4. Only run when needed

================================================================================
ISSUE #2: PERFORMANCE ISSUE ROOT CAUSE
================================================================================

Problems Found:
  
  1. TOO MANY HOOKS
     - save_post: 1 hook
     - wp_trash_post, before_delete_post, untrash_post: 3 hooks
     - created_term, edited_term, delete_term: 3 hooks
     - customize_save_after, wp_update_nav_menu, switch_theme: 3 hooks
     - activated_plugin, deactivated_plugin: 2 hooks
     - WooCommerce hooks: 5 hooks
     - added_option, updated_option, deleted_option: 3 hooks
     - REST API hooks: 2 hooks
     Total: ~23 hooks
     
     Problem: All trigger file updates, causing excessive filesystem writes

  2. UNNECESSARY FRONTEND POLLING
     - reloader.js polls /wp-admin/admin-ajax.php every 500ms (default)
     - Creates 120+ requests per minute
     - Each request hits database
     - No caching on timestamp

  3. LARGE JAVASCRIPT FILES
     - admin-settings.js: 1151 lines (58KB)
     - admin-settings.min.js: 31KB (still large)
     - Loads React and complex UI even when not needed

  4. ADMIN PAGES LOADING ON FRONTEND
     - admin-settings.css loaded on all pages
     - Icon sprites loaded unnecessarily
     - Scroll-to-Top adds extra JS files

Fix:
  1. Consolidate hooks (use action scheduling)
  2. Increase polling interval (1000ms minimum)
  3. Add timestamp caching
  4. Lazy-load admin JS (only on settings page)
  5. Defer non-critical scripts

FIXES PROVIDED:
================================================================================

Fix #1: Defer ini_set() to admin_init
────────────────────────────────────────
Location: reloadify-frontend-sync.php line 123

From:
  add_action( 'plugins_loaded', [ 'Reloadify_Performance', 'apply_runtime_overrides' ], 0 );

To:
  add_action( 'admin_init', [ 'Reloadify_Performance', 'apply_runtime_overrides' ], 0 );

Benefit:
  ✅ Only runs on WordPress admin
  ✅ Database fully initialized
  ✅ Avoids frontend errors


Fix #2: Add error handling to ini_set()
────────────────────────────────────────
Location: class-reloadify-performance.php line 341

From:
  @ini_set( $key, $value );

To:
  if ( function_exists( 'ini_set' ) ) {
      @ini_set( $key, $value );
  }

Benefit:
  ✅ Prevents fatal error
  ✅ Graceful degradation


Fix #3: Reduce polling interval default
────────────────────────────────────────
Location: admin-settings.js or settings

From:
  poll_interval: 500 (milliseconds)

To:
  poll_interval: 2000 (milliseconds) = 2 seconds

Benefit:
  ✅ 75% fewer AJAX requests
  ✅ 75% less server load
  ✅ 75% less database queries
  ✅ Minimal UX impact


Fix #4: Add polling delay randomization
────────────────────────────────────────
In reloader.js:

Add:
  // Stagger requests to prevent thundering herd
  var jitter = Math.random() * 500; // 0-500ms random
  var delayMs = 2000 + jitter;

Benefit:
  ✅ Prevents request spikes
  ✅ Better load distribution
  ✅ Improves server stability


Fix #5: Consolidate update recording hooks
────────────────────────────────────────────
Location: reloadify-frontend-sync.php lines 132-160

Problem:
  Each hook calls record_site_update()
  Each call checks if update needed
  Redundant database writes

Solution:
  Use transient to debounce:
  
  add_action( 'save_post', function() {
      if ( ! wp_next_scheduled( 'reloadify_record_update_cron' ) ) {
          wp_schedule_single_event( time() + 1, 'reloadify_record_update_cron' );
      }
  });
  
  Then process once via cron

Benefit:
  ✅ Multiple updates = 1 database write
  ✅ Significant performance gain


Fix #6: Lazy-load admin styles
────────────────────────────────
Location: Enqueue hooks

From:
  wp_enqueue_style( 'reloadify-admin', ... );
  (loaded on all admin pages)

To:
  if ( 'settings_page_reloadify-frontend-sync' === $screen->id ) {
      wp_enqueue_style( 'reloadify-admin', ... );
  }

Benefit:
  ✅ CSS only loads on settings page
  ✅ Faster other admin pages
  ✅ Smaller payload


Fix #7: Defer frontend script loading
──────────────────────────────────────
Location: wp_enqueue_scripts

Add:
  wp_enqueue_script(
      'reloadify-reloader',
      ...,
      array(),
      ...,
      true  // In footer
  );
  
  // AND add async/defer
  add_filter( 'script_loader_tag', function( $tag, $handle ) {
      if ( 'reloadify-reloader' === $handle ) {
          $tag = str_replace( 'src=', 'async defer src=', $tag );
      }
      return $tag;
  }, 10, 2 );

Benefit:
  ✅ Script doesn't block page load
  ✅ Faster initial page render
  ✅ Better PageSpeed score
